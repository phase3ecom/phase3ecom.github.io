Overview

Why Claude Code (not claude.ai)

You've probably used Claude through the browser at claude.ai. Claude Code is different — and for team work, it's the right tool.

claude.ai (web/app) — each conversation starts blank. No memory of previous sessions. No shared context with teammates. Good for one-off questions.

Claude Code (CLI) — runs in your terminal, reads files from your machine, and loads shared context automatically at the start of every session.

How the memory system works

📄
CLAUDE.md — project-level instructions that load at session start without any prompt. Tells Claude who we are, what stack we use, how to write commit messages, what safety rules to follow. Every team member gets identical baseline behaviour.
📁
memory/ — a folder on Google Drive containing:

rules.md — rules and patterns learned across all client work
projects.md — all active clients: status, pending items, key asset IDs, what's blocked and why
sessions/ — a file per working session recording what was done, what decisions were made, what's still pending

Why this matters for client work

When two people work on the same client:

Person A finishes an email flow, runs /ADMN-wrapup-v2, records "waiting on Steven to confirm free freight offer before activating"

Person B opens Claude Code two days later, runs /ADMN-startup-v2, and immediately sees that pending item — no Slack thread needed.

The bottom line: claude.ai conversations are ephemeral and isolated. This setup is persistent and shared. For client work with multiple people across multiple sessions, that difference matters every day.

Section 02

Install Warp

Warp is the terminal Claude Code runs inside.

Download and install

  1. Go to warp.dev → click Download for macOS
  2. Open the downloaded .dmg file
  3. Drag the Warp icon into the Applications folder
  4. Open Warp from Applications, or press Cmd+Space, type "Warp", press Enter
  5. If macOS shows "Warp was downloaded from the internet" → click Open
  6. Sign in to Warp or skip (optional — sign-in not required)

Apply the Phase 3 Ecom theme

Run these commands in Warp:

mkdir -p ~/.warp/themes cp "setup/warp-theme/Phase 3 Ecom.yaml" ~/.warp/themes/ cp "setup/warp-theme/Phase 3 Ecom.jpg" ~/.warp/themes/

Then in Warp: Settings → Appearance → Theme → Custom → select Phase 3 Ecom

Section 03

Install Google Drive for Desktop

Download and install

  1. Go to google.com/drive/download → click Download Drive for desktop
  2. Open the downloaded installer and follow the prompts
  3. Google Drive launches automatically — sign in with your Phase 3 Ecom Google Workspace account
  4. When prompted, enable both Google Drive and Shared drives
  5. Click Open Google Drive when setup is complete

Confirm the path is accessible

Open Finder and confirm this path exists:

~/Library/CloudStorage/GoogleDrive-[your-email]/Shared drives/Phase 3 Ecom/

Make files available locally

By default, Google Drive streams files from the cloud. Make the workspace folder available locally so Claude Code can read files reliably — including offline.

Option A — Mirror all files (recommended if disk space allows):

  1. Click the Google Drive icon in the menu bar (top right)
  2. Click the gear icon → Preferences
  3. Select the Google Drive tab
  4. Switch from Stream files to Mirror files
  5. Click Save and restart Google Drive when prompted

Option B — Make the folder available offline (lower disk usage):

  1. Open Finder → navigate to ~/Library/CloudStorage/GoogleDrive-[your-email]/Shared drives/Phase 3 Ecom
  2. Right-click the CLAUDE CODE folder
  3. Select Make available offline
  4. Wait for the sync badge to show a green checkmark
Once files are local, Claude Code reads and writes without depending on internet speed for every file access.

Section 04

Install Node.js (18+)

Claude Code requires Node.js 18 or higher. Choose one of the options below — both install the same thing.

Option A — Homebrew (if already installed)

Open Warp and run:

brew install node

No Homebrew yet? Get it from brew.sh — paste the one-line install command into Warp, then run brew install node once it finishes.

Password prompt is normal. Homebrew may ask for your macOS login password to fix directory permissions on first use. Enter your normal Mac login password — this is not a security concern.

Option B — Direct installer (no Homebrew required)

  1. Go to nodejs.org → click the LTS (Long Term Support) button to download
  2. Open the downloaded .pkg file
  3. Click through the installer wizard → Continue → Install → Close

Verify in Warp

Open Warp and run both commands. Both should return a version number.

node --version # should show v18.0.0 or higher npm --version
If node --version says "command not found", close Warp completely and reopen it — the installer updates your PATH but Warp needs to reload.

Also install jq

The Warp plugin requires jq (a JSON tool). Install it now:

brew install jq

Verify with:

jq --version

Section 06

Run Setup Script

Installs hooks (caveman mode, sound notifications), skills, Claude Code settings, and the Warp theme.

cd "/Users/[your-username]/Library/CloudStorage/GoogleDrive-[your-email]/Shared drives/Phase 3 Ecom/CLAUDE CODE" bash setup/install.sh

Replace [your-username] and [your-email] with your actual values.

What this installs

  • Hooks — caveman mode + completion sound (plays when Claude finishes and waits for your input)
  • Skills — 11 P3E-approved skills: /ADMN-startup-v2, /ADMN-wrapup-v2, /ADMN-client-onboard-v1 + 8 others
  • Warp theme — copied to ~/.warp/themes/ with correct path
  • ~/.claude/settings.json — hooks, status line, plugin config
Completion sound: The Stop hook plays a chime via macOS's built-in afplay command whenever Claude finishes and is waiting for your next prompt. Sound file installed to ~/.claude/sounds/ automatically.

After this step: in Warp → Settings → Appearance → Theme → Custom → Phase 3 Ecom

Skills: P3E approved vs local

Skills power slash commands like /ADMN-startup-v2. Two tiers:

  • P3E Approved (Drive) — skills in CLAUDE CODE/Skills/ on the Shared Drive. Reviewed by Will, follow CATEGORY-skill-name-vN naming, and sync automatically at every session start via /ADMN-startup-v2.
  • Local only — skills installed via npx skills add or /plugin marketplace add. Personal use only — not P3E standard, not synced to Drive.
Rule: Never modify a Drive-synced skill locally — the next /ADMN-startup-v2 will overwrite it. Skills catalog: Skills/skills-catalog.xlsx

To submit a skill for P3E use: Create a task in ClickUp → P3E Admin → Skill Submissions list. Attach the SKILL.md file. Will reviews and publishes — your next session start picks it up automatically.

Install Plugins

Run these commands in Warp (not inside a Claude Code session — just at the terminal prompt):

claude plugin install superpowers@claude-plugins-official claude plugin install caveman@caveman claude plugin install warp@claude-code-warp

Wait for each to finish before running the next. Restart Claude Code after all three are installed.

Note: The old /install slash command no longer exists. Use claude plugin install from the terminal instead.

Section 08

Set Up ccstatusline

ccstatusline shows live Claude session stats in the Warp status bar at the bottom of your terminal window.

Already installed. The setup script in Section 06 configured it automatically via settings.json. No manual action needed.

Verify it's working

Start a Claude Code session, then look at the bottom of the Warp window. You should see:

Model: Sonnet 4.6 | Ctx: 138.4k | Ctx Used: 69.0%

This displays on the dark navy background of the Phase 3 Ecom Warp theme installed in Section 02. No additional colour configuration needed — colours are set by the theme.

What each metric means

MetricWhat it shows
ModelWhich Claude model is active this session (e.g. Sonnet 4.6)
CtxTotal context tokens used so far this session
Ctx Used %Percentage of the context window consumed

If nothing appears in the status bar

Run this once, then restart Claude Code:

npx ccstatusline@latest
The critical rule: when Ctx Used hits ~50%, wrap the session (/ADMN-wrapup-v2) and start fresh. Quality degrades significantly past that point. See Section 12 for the full 50% Rule.

Section 12

The 50% Rule + Session Rules

Claude's context window fills as a session progresses. At 50% full, quality degrades — Claude forgets instructions, hallucinates details, repeats itself.

Context quality

Context UsedQuality
0–30%Fresh, sharp, best-quality work
30–50%Still functional, starting to lose edge
50–70%Noticeable degradation: forgetting, repeating, small mistakes
70–90%Significant degradation: wrong answers, missed context
90%+Unreliable — often worse than useless

When you hit 50%

  • Ask Claude: "Summarise what we accomplished and what's pending"
  • Run /ADMN-wrapup-v2
  • Close terminal tab, open new one, run claude, then /ADMN-startup-v2
  • Continue from ~15–25% context
Never use /compact. Always /ADMN-wrapup-v2 + fresh session.

Session rules

Session Management
  • Always run /ADMN-startup-v2 at the start of every session
  • Always run /ADMN-wrapup-v2 before closing
  • Wrap at 50% context — watch ccstatusline
  • One project per session — no client context-switching
  • Never use /compact
Git & Code
  • Never push directly to main — always branch + PR
  • Never commit .env files
  • Commit frequently — after each meaningful change
  • Commit messages: Add: Fix: Update: Remove: prefix + why
Client Work
  • Never publish campaigns, ads, or flows without explicit approval from Will
  • Ask before destructive operations (delete branches, drop data, force-reset)
  • Never fabricate metrics — use placeholders if data unavailable
  • Australian English in all client deliverables (spelling, DD/MM dates, AUD)

Help

Troubleshooting

/ADMN-startup-v2 can't find memory

Memory lives at memory/ in the CLAUDE CODE root. From a client folder it's at ../../memory/. Check you're inside the Google Drive path.

MCP not working

Each MCP is connected per user in your claude.ai account — not shared. Reconnect at claude.ai → Settings → Integrations.

Hooks not firing (no caveman mode, no sound)

Re-run bash setup/install.sh. Check ~/.claude/settings.json exists and has a hooks section.

Plugin not found

Make sure you're running Claude Code from the correct folder. Reinstall via terminal: claude plugin install [plugin]@[marketplace]

Google Drive path wrong

The path varies by your Google account email. Run the following to find your exact path:

ls ~/Library/CloudStorage/

Stop hook error: jq: command not found

The Warp plugin requires jq. Install it:

brew install jq

Restart Claude Code after installing.
