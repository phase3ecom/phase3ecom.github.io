🔧 02 — Install

🖥️
Step 01
Install Warp

Warp is the terminal Claude Code runs inside. Download the Windows installer from warp.dev, install, and open. Sign-in is optional.

Apply the Phase 3 Ecom theme:

  • 1Open File Explorer and navigate to (create the folder if it doesn't exist):
    %APPDATA%\Warp\data\themes\
  • 2Copy both files from the shared drive into that folder:
    setup\warp-theme\Phase 3 Ecom.yaml
    setup\warp-theme\Phase 3 Ecom.jpg
  • 3Open the copied Phase 3 Ecom.yaml in Notepad and replace the path: line with your actual path:
    path: C:\Users\[your-username]\AppData\Roaming\Warp\data\themes\Phase 3 Ecom.jpg
  • 4In Warp: Settings → Appearance → Theme → Custom → Phase 3 Ecom
🪟 Can't find %APPDATA%? Press Win + R, type %APPDATA%, press Enter. Navigate to Warp\data\themes\ from there.

Step 05
Run the Phase 3 Ecom Setup Script (Git Bash)

The setup script is a bash file — it requires Git Bash (included with Git for Windows from git-scm.com).

Open Git Bash (search Start menu for "Git Bash"), then run:

Git Bash

🪟 Drive letter in Git Bash: Git Bash maps G:\ as /g/. If your Google Drive mounted to a different letter (e.g. H:\), use /h/ instead.

The script installs:

  • ✓Hooks — caveman mode + session end sound (to %USERPROFILE%\.claude\hooks\)

  • ✓Warp theme — copies to %APPDATA%\Warp\data\themes\ with correct path
  • ✓settings.json — to %USERPROFILE%\.claude\settings.json

🧠 Session Management

📊
Step 11
Install ccstatusline

ccstatusline adds a live status bar to your Claude Code sessions showing context %, model, session cost, git branch, and more. The single most useful tool for context awareness — install before starting serious client work.

Run once in Windows Terminal or PowerShell (outside Claude Code):

PowerShell / Windows Terminal
npx ccstatusline@latest

A menu appears. Use arrow keys to select items. Press Enter to save. Config writes automatically to your Claude Code settings. Next time you start claude, the status bar appears.

Reconfigure anytime — run the same command again, pick different items, restart Claude.

What it shows
  • →Context % — live percentage of your context window used. The number you watch for the 50% rule.
  • →Model — which Claude model is active (Opus / Sonnet / Haiku). Prevents doing serious work on a smaller model by accident.
  • →Session cost — running token cost of the current session.
  • →Git branch — the branch Claude is working in. Prevents commits to the wrong branch.
  • →Session time — how long this session has been active.
Recommended config for marketers

Minimum (start here): Context %, Model, Session Cost — covers the 50% rule, model check, and bill awareness.

Add if needed: Git branch (if you push to GitHub often), Session time (if you lose track of how long you've been in a session).

💡 Don't overload the bar — every extra item takes space from the important ones. Start with 3–4 items.
⚡
The Most Important Rule
The 50% Rule

Claude's context window fills as a session progresses. At 50% full, quality starts degrading — Claude forgets instructions, hallucinates details, repeats itself. The 50% rule is the discipline that prevents this.

Why it degrades
Context UsedQuality
0–30%Fresh, sharp, best-quality work
30–50%Still functional, starting to lose edge
50–70%Noticeable degradation: forgetting, repeating, small mistakes
70–90%Significant degradation: wrong answers, missed context, made-up details
90%+Unreliable — often worse than useless

50% is where the curve bends. Push past it = more errors, more re-work, slower overall. Wrapping at 50% takes 2–3 minutes. Fixing mistakes from a full context takes far longer.

The /wrapup + restart workflow
  • 1When context hits 50%, ask Claude: "Summarise what we accomplished and what's pending"
  • 2Run /wrapup — saves to memory, commits, pushes
  • 3Close the terminal tab
  • 4Open a new Warp tab in the same folder → claude → /startup
  • 5Claude reads the saved memory. Continue from ~15–25% context.
If you're mid-flow at 50%

Do it anyway. Before running /wrapup, ask for a verbose summary first:

Before we /wrapup — I'm mid-flow on [task]. Write a very detailed
summary of what we've done, the next specific steps, and any
decisions made that might get lost. Then /wrapup with that summary.

Next session's /startup loads this summary. Ramp-up becomes 30 seconds instead of 5 minutes.

⚠️ Never use /compact. It compresses context but loses the useful details while keeping confusing fragments. Always /wrapup + fresh session instead — same time, clean start.
Symptoms of a full context
  • !Claude re-creates something you already built
  • !Claude asks about a preference you already set
  • !Outputs get more generic and vague
  • !Claude gets confused about which project you're in
  • !Responses start taking longer

Any of these = probably over 50%. Run /wrapup immediately.

Non-Negotiable
Session Rules

These rules apply to every session, every project, every team member. No exceptions.

Session Management
  • ✓Always run /startup at the start of every session — loads memory, clients, rules, last session context.
  • ✓Always run /wrapup before closing — saves summary, updates pending items, records new rules.
  • ✓Wrap at 50% context — check ccstatusline. When context hits 50%, stop, /wrapup, fresh session.
  • ✓One project per session — don't context-switch between clients mid-session. Finish one, /wrapup, then start the next.
  • ✓Never use /compact — always /wrapup + fresh session instead.
Git & Code
  • ✓Never push directly to main — always use a branch and PR.
  • ✓Never commit .env files — these contain live API keys. The .gitignore blocks them; never override it.
  • ✓Commit frequently — after each meaningful change, not in bulk at the end.
  • ✓Commit message format — action prefix + why: Add: Fix: Update: Remove:
Client Work
  • ✓Never publish campaigns, ads, or flows without explicit approval from Will.
  • ✓Ask before destructive operations — deleting branches, dropping data, force-resetting.
  • ✓Never fabricate metrics — use clearly marked placeholders if data is unavailable.
  • ✓Australian English — spelling, date formats (DD/MM), currency (AUD) in all client deliverables.

🛠️ Troubleshooting
claude not found after install
Restart Windows Terminal or Warp to refresh PATH. If still missing, check npm config get prefix — the bin folder shown must be on your PATH. Add it via System Properties → Environment Variables → Path.
Setup script fails in Git Bash
Confirm Git Bash can see the Google Drive path. Run ls /g/ — if empty, your drive letter may be different. Check File Explorer → This PC to confirm the correct letter, then substitute in all commands.
/startup can't find memory
Memory lives at memory\ in the CLAUDE CODE root on Google Drive. Open Claude Code from the correct folder — the CWD determines where memory is found. From a client folder it looks two levels up (..\..\memory\).
MCP not working
Each MCP connects per user in your own claude.ai account — not inherited. Reconnect at claude.ai → Settings → Integrations.
Hooks not firing (no caveman mode, no sound)
Re-run bash setup/install.sh in Git Bash. Check that %USERPROFILE%\.claude\settings.json exists and contains a hooks section. Node.js must be on PATH for hooks to execute.
Warp theme not appearing
Confirm the .yaml and .jpg are both in %APPDATA%\Warp\data\themes\. Open the YAML in Notepad and verify the path: line points to your actual username (not [your-username]). Restart Warp after copying.
