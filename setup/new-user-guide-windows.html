Overview

Why Claude Code (not claude.ai)

You've probably used Claude through the browser at claude.ai. Claude Code is different — and for team work, it's the right tool.

claude.ai (web/app) — each conversation starts blank. No memory of previous sessions. No shared context with teammates. Good for one-off questions.

Claude Code (CLI) — runs in your terminal, reads files from your machine, and loads shared context automatically at the start of every session.

How the memory system works

CLAUDE.md — project-level instructions that load at session start without any prompt. Tells Claude who we are, what stack we use, how to write commit messages, what safety rules to follow. Every team member gets identical baseline behaviour.

memory/ — a folder on Google Drive containing:

  • rules.md — rules and patterns learned across all client work
  • projects.md — all active clients: status, pending items, key asset IDs, what's blocked and why
  • sessions/ — a file per working session recording what was done, what decisions were made, what's still pending

Why this matters for client work

When two people work on the same client:

  • · Person A finishes an email flow, runs /ADMN-wrapup-v1, records "waiting on Steven to confirm free freight offer before activating"
  • · Person B opens Claude Code two days later, runs /ADMN-startup-v1, and immediately sees that pending item — no Slack thread needed

The bottom line: claude.ai conversations are ephemeral and isolated. This setup is persistent and shared.

Section 02

Install Git for Windows

Git for Windows provides Git Bash — the Unix shell that Warp uses underneath. You won't open Git Bash directly. After configuring Warp in Section 03, all terminal commands run inside Warp. Install Git first so Warp has a shell to use.

Neither Claude Code nor Warp can install Git for you. This must be done manually first.

Option A — winget (recommended, Windows 11 built-in)

Open PowerShell (search Start menu → type "powershell") and run:

winget install Git.Git

Follow the prompts. Git installs automatically. No browser required.

PowerShell open — paste the command and press Enter
winget install Git.Git running — wait for "Successfully installed" before continuing

Option B — manual download

  1. Go to git-scm.com → click Download for Windows
  2. Run the downloaded Git-[version]-64-bit.exe installer
  3. Click through the wizard — default options are fine for all steps
  4. On the Choosing the default editor screen: leave as Vim (default) or change to Notepad — doesn't matter
  5. Click Install → Finish

Verify

Open PowerShell (Start menu → search "powershell") and run:

git --version

Should output something like git version 2.x.x.windows.x. After configuring Warp in Section 03, all commands run inside Warp — PowerShell is only used here for this one check.

One terminal only: After Section 03, Warp is the only terminal you'll use. Git Bash is the shell running inside Warp — you never open it separately. All commands in this guide are typed into Warp.
What you should see in your browser — guide open at S02

Warp is the terminal Claude Code runs inside.

Download and install

  2. Run the downloaded installer (.exe)
  3. Follow the installation wizard → Next → Install → Finish
  4. Launch Warp from the Start menu or desktop shortcut
  5. Sign in to Warp or skip (optional — sign-in not required)
warp.dev — click "Download for Windows"
Warp download page — download starts automatically
"You're about to get Warp" — confirm the download
"Welcome to Warp" — first launch splash screen
"What brings you to Warp?" onboarding + "Open Warp?" browser dialog

Configure Warp to use Git Bash

Warp needs to use Git Bash as its shell so all commands work correctly.

  1. Open Warp → click the gear icon (Settings) top right
  2. Go to Features → Sessions
  3. Under Default shell, click the dropdown → select Git Bash
    If it doesn't appear, click Browse and navigate to C:\Program Files\Git\bin\bash.exe
  4. Close Settings → fully close and reopen Warp
After this step, Warp runs Git Bash. All commands in the rest of this guide are typed into Warp. Never open Git Bash separately.

Apply the Phase 3 Ecom theme

The setup script in Section 07 copies the theme files automatically. Once you've run it, enable the theme in Warp: Settings → Appearance → Theme → Custom → select Phase 3 Ecom

Section 04

Install Google Drive for Desktop

Download and install

  1. Go to google.com/drive/download → click Download Drive for desktop
  2. Run the downloaded GoogleDriveSetup.exe installer
  3. Follow the prompts → sign in with your Phase 3 Ecom Google Workspace account
  4. When prompted, enable Shared drives
  5. Google Drive mounts as a virtual drive — usually G:

Confirm the path is accessible

Open File Explorer and confirm this path exists:

G:\Shared drives\Phase 3 Ecom\
If your Drive mounted to a different letter (e.g. H:), use that letter instead throughout this guide. Check File Explorer → This PC to find it.
File Explorer → This PC — Google Shared Drives mounted (usually G:)

Make files available locally

By default, Google Drive streams files from the cloud. Make the workspace folder available locally so Claude Code can read files reliably — including offline.

Option A — Mirror all files (recommended if disk space allows):

  1. Right-click the Google Drive icon in the system tray (bottom right)
  2. Click the gear icon → Preferences
  3. Select the Google Drive tab
  4. Switch from Stream files to Mirror files
  5. Click Save and allow Drive to restart

Option B — Make the folder available offline (lower disk usage):

  1. Open File Explorer → navigate to G:\Shared drives\Phase 3 Ecom
  2. Right-click the CLAUDE CODE folder
  3. Select Make available offline
  4. Watch the system tray for sync progress — wait for it to complete
Once files are local, Claude Code reads and writes without depending on internet speed for every file access.

Install Node.js (18+)

Open Warp and run:

Node.js installs automatically. Close and reopen Warp when it finishes.

Option B — manual installer

  1. Go to nodejs.org → click the LTS button
  2. Download the Windows Installer (.msi)
  3. Run the installer → click through all defaults → Finish
  4. Close and reopen Warp after install completes

Verify in Warp

Open Warp and run both commands. Both should return a version number.

node --version # should be 18+ npm --version
If node --version says "command not found", close Warp completely and reopen — the installer updates PATH but Warp needs to reload it.

Also install jq

The Warp plugin requires jq (a JSON tool). Install it now:

winget install jqlang.jq

Close and reopen Warp when done. Verify with:

jq --version

Section 05b

Configure PowerShell Execution Policy

Windows blocks npm-installed tools (including Claude Code) from running by default. You need to allow scripts once before continuing.

Why this matters: npm installs tools as .ps1 scripts. PowerShell's default policy (Restricted) blocks them — so running claude after install will fail with a "cannot be loaded" error unless you do this step first.

Run in PowerShell

Open PowerShell (Start menu → search "powershell") and run:

Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
The .ps1 error you'll see without this fix, then Set-ExecutionPolicy resolving it

Type Y and press Enter when prompted. This only affects your user account — no admin rights required.

Verify

Get-ExecutionPolicy -Scope CurrentUser

Should output RemoteSigned. Close PowerShell — all remaining steps use Warp.

Section 07

Run Setup Script

Open Warp:

cd "/g/Shared drives/Phase 3 Ecom/CLAUDE CODE" bash setup/install.sh
File Explorer in Phase 3 Ecom Drive — Warp opening alongside
Warp in the CLAUDE CODE folder — run bash setup/install.sh

Warp (with Git Bash) maps Windows drive letters to Unix paths: G:\ = /g/, H:\ = /h/, etc. If your Google Drive mounted to a different letter, replace /g/ with the correct letter.

What this installs

  • Hooks — caveman mode + completion sound hook (to %USERPROFILE%\.claude\hooks\)
  • Skills — 11 P3E-approved skills: /ADMN-startup-v1, /ADMN-wrapup-v1, /ADMN-client-onboard-v1 + 8 others
  • %USERPROFILE%\.claude\settings.json — hooks, status line, plugin config

If settings.json already exists, the script prompts you to merge manually.

Sound notification works on Windows. The setup script installs a cross-platform play-sound.sh hook. On Windows it uses PowerShell's SoundPlayer to play the same WAV notification that macOS plays via afplay. No extra software needed.

After this step: in Warp → Settings → Appearance → Theme → Custom → Phase 3 Ecom

Skills: P3E approved vs local

Skills power slash commands like /ADMN-startup-v1. Two tiers:

  • P3E Approved (Drive) — skills in CLAUDE CODE/Skills/ on the Shared Drive. Reviewed by Will, follow CATEGORY-skill-name-vN naming, and sync automatically at every session start.
  • Local only — skills installed via npx skills add or /plugin marketplace add. Personal use only — not P3E standard, not synced to Drive.
Rule: Never modify a Drive-synced skill locally — the next /ADMN-startup-v1 will overwrite it. Skills catalog: Skills/skills-catalog.xlsx

To submit a skill for P3E use: Create a task in ClickUp → P3E Admin → Skill Submissions list. Attach the SKILL.md file. Will reviews and publishes — your next session start picks it up automatically.

Section 09

Set Up ccstatusline

ccstatusline shows live Claude session stats in the Warp status bar at the bottom of your terminal window.

Already installed. The setup script in Section 07 configured it automatically via settings.json. No manual action needed.

Verify it's working

Start a Claude Code session, then look at the bottom of the Warp window. You should see:

Model: Sonnet 4.6 | Ctx: 138.4k | Ctx Used: 69.0%
ccstatusline visible in Warp status bar — model, context size, and usage %

This displays on the dark navy background of the Phase 3 Ecom Warp theme installed in Section 03. No additional colour configuration needed — colours are set by the theme.

What each metric means

MetricWhat it shows
ModelWhich Claude model is active this session (e.g. Sonnet 4.6)
CtxTotal context tokens used so far this session
Ctx Used %Percentage of the context window consumed

If nothing appears in the status bar

In Warp, run this once, then restart Claude Code:

npx ccstatusline@latest
The critical rule: when Ctx Used hits ~50%, wrap the session (/ADMN-wrapup-v1) and start fresh. Quality degrades significantly past that point. See Section 13 for the full 50% Rule.

Section 13

The 50% Rule + Session Rules

Claude's context window fills as a session progresses. At 50% full, quality degrades — Claude forgets instructions, hallucinates details, repeats itself.

Context quality

Context UsedQuality
0–30%Fresh, sharp, best-quality work
30–50%Still functional, starting to lose edge
50–70%Noticeable degradation: forgetting, repeating, small mistakes
70–90%Significant degradation: wrong answers, missed context
90%+Unreliable — often worse than useless

When you hit 50%

  • Ask Claude: "Summarise what we accomplished and what's pending"
  • Run /ADMN-wrapup-v1
  • Close terminal tab, open new one, run claude, then /ADMN-startup-v1
  • Continue from ~15–25% context
Never use /compact. Always /ADMN-wrapup-v1 + fresh session.

Session Management

  • ✅ Always run /ADMN-startup-v1 at the start of every session
  • ✅ Always run /ADMN-wrapup-v1 before closing
  • ✅ Wrap at 50% context — watch ccstatusline
  • ✅ One project per session — no client context-switching
  • ✅ Never use /compact

Git & Code

  • ✅ Never push directly to main — always branch + PR
  • ✅ Never commit .env files
  • ✅ Commit frequently — after each meaningful change
  • ✅ Commit messages: Add: Fix: Update: Remove: prefix + why

Client Work

  • ✅ Never publish campaigns, ads, or flows without explicit approval from Will
  • ✅ Ask before destructive operations (delete branches, drop data, force-reset)
  • ✅ Never fabricate metrics — use placeholders if data unavailable
  • ✅ Australian English in all client deliverables (spelling, DD/MM dates, AUD)

Troubleshooting

Common Issues

/ADMN-startup-v1 can't find memory
Memory lives at memory/ in the CLAUDE CODE root. From a client folder it's at ../../memory/. Check you're inside the Google Drive path.
MCP not working
Each MCP is connected per user in your claude.ai account — not shared. Reconnect at claude.ai → Settings → Integrations.
Hooks not firing (no caveman mode)
Re-run bash setup/install.sh in Warp. Check %USERPROFILE%\.claude\settings.json exists and has a hooks section.
Plugin not found
Make sure you're running Claude Code from the correct folder. Run /install [plugin] again.
Google Drive path wrong
Check File Explorer → This PC to find your Drive letter. Use that letter in all paths above (e.g. /h/ instead of /g/ in Warp).
Sound not working
Re-run bash setup/install.sh in Warp — it copies both play-sound.sh and the .wav file to %USERPROFILE%\.claude\. If sound still fails, in Warp run: bash ~/.claude/hooks/play-sound.sh. Ensure your Windows volume is not muted.
